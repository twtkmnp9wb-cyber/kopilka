# Копилка

Пет-проект: доходы и расходы на графиках, цели с дедлайном, рекомендуемый бюджет на месяц,
«можно тратить сегодня» и прогноз накоплений на 3–24 месяца. Лендинг с 3D-купюрой на three.js
и параллаксом от курсора, наклона телефона и прокрутки.

**Сайт:** https://twtkmnp9wb-cyber.github.io/kopilka/ · есть демо-режим без регистрации.

## Как считается бюджет

```
свободный лимит = ожидаемый доход − обязательные платежи − взносы в цели − подушка
```

- **Ожидаемый доход** — сумма регулярных доходов; если их нет, среднее за прошлые 3 месяца;
  если в этом месяце уже пришло больше — фактическая сумма.
- **Обязательные** — регулярные платежи (аренда, связь, подписки) или средние траты обязательных категорий.
- **Взнос в цель** — остаток на начало месяца, делённый на месяцы до дедлайна, с округлением вверх до рубля.
  Статус «отстаёшь» — сравнение с линейным графиком от даты создания цели.
- **Подушка** — процент от дохода (по умолчанию 10%).
- Свободный лимит делится по необязательным категориям пропорционально тратам прошлых месяцев.
- **Можно тратить сегодня** = (лимит − необязательные траты до сегодня) / оставшиеся дни.
- **Прогноз**: каждый месяц = доход − обязательные − типичные необязательные траты; взносы перекладывают
  деньги в цели до их достижения. Коридор — σ необязательных трат × √k.

Если взносы не помещаются в доход, Копилка показывает, к какому месяцу цель реально накопится.

## Архитектура

Чистые слои, зависимости направлены только внутрь (проверяется ESLint-правилами):

```
src/
  domain/          чистый TypeScript: деньги в копейках, периоды, сущности, расчёты (+ тесты)
  application/     порты (интерфейсы хранилищ и авторизации), сценарии, схемы форм, read-модели
  infrastructure/  Supabase-репозитории и авторизация, localStorage для демо, composition root
  ui/
    app/           провайдеры, выбор режима (облако/демо), сессия, роутинг
    shared/        дизайн-токены, компоненты, графики, хуки данных (TanStack Query)
    features/      landing (3D), auth, dashboard, transactions, goals, plan, settings
```

- Хранилище подменяется одной реализацией порта: демо-режим работает на тех же сценариях, что и облако.
- Деньги — целые копейки, распределение лимитов — методом наибольших остатков (сумма частей точно равна целому).
- three.js живёт в лениво загружаемом чанке лендинга; без WebGL или при `prefers-reduced-motion` — статичная купюра
  того же дизайна (рисуется теми же функциями canvas).

## Стек

React 19 · TypeScript (strict) · Vite · TanStack Query · React Router · react-hook-form + zod · Recharts ·
three.js / @react-three/fiber / drei · Supabase (Postgres + RLS + Auth) · Vitest · ESLint · GitHub Actions → Pages.

## Запуск

```bash
npm install
npm run dev
```

Проверки: `npm run lint`, `npm test`, `npm run build`.

## Деплой

`npm run deploy` — проверки, сборка и публикация `dist` в ветку `gh-pages` (Pages настроен на «Deploy from a branch»).
Готовый GitHub Actions workflow лежит в [`docs/ci/deploy.yml`](docs/ci/deploy.yml): чтобы деплой шёл сам на каждый push,
перенеси его в `.github/workflows/` и переключи Pages на «GitHub Actions» (для пуша workflow-файла токену нужно право `workflow`).

## База данных

Схема — [`supabase/setup.sql`](supabase/setup.sql): таблицы `fin_*` с RLS «только свои строки» и составными
внешними ключами, которые не дают сослаться на чужую категорию или цель. Выполнить один раз в Supabase → SQL Editor.
Параметры проекта — в `.env` (publishable-ключ публичный по задумке), свои можно задать в `.env.local`.
